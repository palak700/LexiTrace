# Prediction investigation

The current real document checkpoint was tested on four synthetic diagnostic inputs. These controls are not a held-out dataset and do not establish project accuracy.

The checkpoint's class order was Human, AI-Generated, AI-Edited Human. Its classifier head had shape [3, 768]. For each short input, backend windowed inference probabilities matched a direct tokenizer/model/softmax call exactly (maximum absolute difference 0.0).

| Synthetic control | Human | AI-Generated | AI-Edited Human | Predicted class |
|---|---:|---:|---:|---|
| Personal-style narrative | 0.16946949 | 0.00467370 | 0.82585686 | AI-Edited Human |
| Formal-style explanatory prose | 0.00104839 | 0.98879969 | 0.01015190 | AI-Generated |
| Programming-style explanation | 0.06962317 | 0.06607054 | 0.86430633 | AI-Edited Human |
| Repeated-word control | 0.48681611 | 0.11817965 | 0.39500424 | Human |

The prose controls were generated by the assistant, not human originals subsequently edited by AI. Their misclassification demonstrates that the checkpoint can confuse fully generated prose with edited-human prose, including at high softmax confidence. The repeated-word control has no meaningful authorship ground-truth label and is not counted as an accuracy example.

No label-index or probability-display error was identified in these checks. This does not rule out extraction/preprocessing problems on the user's specific document. No failing user example or trustworthy held-out dataset was available during the investigation. Model weights, labels, decision thresholds and submitted user data were not changed to force expected answers.

Next required evidence: one actual failing input, returned label/probabilities, expected label and known writing provenance; the original PDF/text file is also needed if extraction is suspected. Then reproduce that exact input, compare extracted versus intended text, and evaluate a representative independent labeled set before deciding whether preprocessing or model retraining is required.
